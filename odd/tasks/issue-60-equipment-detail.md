## Design decisions

- D1 Header: back link, "Equipo: <interno> - <tipo de equipo>", state badge, a primary "Registrar horas" button (only with `reading.write` at the equipment's position and an open meter) and a "Más acciones" menu with the existing actions (edit, assign / move / replace / end / correct, archive / restore), each gated as today. The existing dialogs are reused; none is rewritten.
- D2 Top row of four cards, as in the mockup: Información general (interno, tipo, marca / modelo, año, n° de serie, batería, with the photo), Ubicación actual (operación, site, negocio = división, proveedor, with "Cambiar operación / site" = the move dialog, or "Asignar" when unassigned), Horas y mantenimiento, Gráfico de uso. There is no supplier internal number in the model: that row of the mockup is left out.
- D3 Horas y mantenimiento follows the previous project's rule. Base = the last registered preventive, and while preventives do not exist (a later issue), the first reading of the open meter. Next = base + interval of the asset type; consumed = current − base (never below 0); remaining = next − current; ring = consumed / interval, capped at 100%. State: Vencido when remaining ≤ 0; Próximo a vencer when consumed > 75% of the interval (rule of `docs/00-analisis-inicial.md`, not the 50 h of the previous project); else Vigente. The card also shows the current reading and the hours of the current calendar month. Units follow the meter (h or km). Without a meter, without readings or without an interval the card says what is missing instead of numbers.
- D4 Gráfico de uso: hours (or km) of each month of the current year, Ene to Dic, computed from the readings (the same segment rule as the 30-day total), drawn as an SVG line with no chart library. No "horas contratadas" line: contracts do not exist yet.
- D5 The month and year windows are calendar periods in the tenant's day (UTC dates like the rest of the readings). The pure rules live in the domain (`src/fleet/domain` for the preventive state, `src/metering/domain` for the monthly totals) with strict TDD; the page composes them through use cases only.
- D6 Below the cards: tabs Historial (default) and Lecturas, the same content as today; then the Observaciones card. The Información tab goes away (its content is the top row). `?tab=info` falls back to Historial.
- D7 Copy in `app/_lib/copy.ts`; the responsive layout stacks the cards on a phone.
